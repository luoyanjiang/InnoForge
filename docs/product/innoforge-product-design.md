## 1. 整合原则（必须遵守）

1. **不丢弃 Intent OS**：意图创建、数字孪生、Agent 采纳/拒绝、Credit 质押与兑现、发现参与、确认调度、判断历史与权益归因，全部保留为闭环一等环节。  
2. **叠加 InnoForge**：工作台意图卡片与 Lumen、多角色协商、具身协作画布、制造参数、受控物理部署、生命体演化、治理审批与审计，作为同一闭环的延伸层。  
3. **叠加 v0.4 研究系统愿景**：六大能力、三场景（产品/科研/硬件）、分层架构、任务树、资产空间与经济系统作为**同一操作系统的上层能力地图**，映射到现有闭环，不另起产品。  
4. **一条闭环，一个产品**：数字意图 → 多代理协作确认 → 受控物理部署 → 治理与反馈 → 价值兑现 / 生命体演化。  
5. **经济双轨并存（原型）**：Credit 质押/铸造/分配（Intent OS）与订阅/打样计费叙事（InnoForge）并存；v0.4 积分/声誉/资产分成是同一激励层的远期扩展。

---

## 2. 一句话定位

**InnoForge** 是承载 Intent OS 的**创造流程操作系统**与受控物理执行网关：让人类意图可见、可协商、可确认，并可在确认后进入制造与反馈；壁垒在意图管理、协作协议、可组合资产与验证闭环，而非通用模型能力本身。

---

## 3. 完整闭环（整合）

```
创建意图（Credit 质押 · 场景模式）
  → 意图树对齐（目标 / 约束 / 成功标准 · 版本）
  → 工作台 / 孪生（意图卡片 · Lumen · Agent/变体采纳拒绝）
  → 协作画布（阶段状态机 · 多角色协商 · 裁决入责任链）
  → 可制造参数与确认调度（人类确认后才消耗资源）
  → 治理审批 · 部署执行 · 现实反馈
  → 生命体演化提案（可选）
  → 真实价值兑现（Credit 铸造与归因分配）
  → 发现与异步再参与 · 资产沉淀（远期）
```

| 环节 | Intent OS 来源 | InnoForge 来源 | v0.4 叠加 | 原型界面 |
|------|----------------|----------------|-----------|----------|
| 个人总览 | 意图库、Credit、声誉、权益预览 | — | 场景模式切换 | 总览 |
| 创建意图 | 意图定义、约束、Credit 质押 | 垂直模板 | 场景种子（产品/科研/硬件） | 创建意图 |
| 意图对齐 | 约束边界 | — | **意图树一等公民** | **意图树** |
| 展开与确认 | 孪生、Agent 候选采纳/拒绝 | 意图卡片、变体、Lumen | 树节点回流 | 工作台 |
| 多角色协作 | 异步判断接力 | Collaborative、协商、具身 | **协作阶段状态机** | 协作 |
| 发现参与 | 发现项目、质押、潜在权益 | 项目 / 生命体 | 资产市场入口（远期） | 发现 |
| 调度与制造 | 确认调度、锁定版本 | 制造参数、部署、供应链 | 硬件插件仿真编排（远期） | 部署 |
| 治理与历史 | 意图与判断历史 | Governance、审计、回滚 | 贡献可审计 | 治理 · 历史 |
| 权益与兑现 | 贡献权益、价值兑现 | 生命体提案 | 经济系统（积分→真钱） | 权益 |

## 5. 三场景（IA 一等模式，不拆成三产品）

共享底座：意图树、协作协议、Credit/贡献、部署网关。差异用**场景模式**切换文案、阶段标签与默认树模板：

| 模式 | 焦点 | 协作阶段文案（产品创新默认） | 验证形态 |
|------|------|------------------------------|----------|
| **产品** `PRODUCT` | 商业目标 / 用户问题 / 增长 | 定义 → 原型 → 实现 → 验证 | 原型与用户/代理测试 |
| **科研** `RESEARCH` | 假设 / 证据 / 可证伪 | 假设 → 设计 → 实验 → 分析 | 实验流水线与复现 |
| **硬件** `HARDWARE` | 约束优先 / 仿真 / 打样 | 约束 → 设计 → 仿真 → 打样 | 仿真-实测闭环 |

首垂仍为**小批量结构件**（硬件切入点），产品模式为默认演示场景；科研为第二曲线。

## 7. 信息架构（产品层 · v1.8 纠正）

**权威**：[产品方案 v0.4](./innoforge-product-方案-v04.md) §2–§4。

| 原则 | 说明 |
|------|------|
| **Project 主容器** | 意图树 + 任务树 + 项目资产 + 协作阶段同属项目，随项目走 |
| **任务不并列顶层** | 禁止「任务空间」与项目平级；个人任务仅为 assignments 视图 |
| **空间 ≠ 任务看板** | Personal / Team / Project spaces 管资产与权限 |
| **Intent OS 闭环保留** | 质押 · 工作台判断 · 确认部署 · 治理权益仍可达 |

**F1 壳层（已合入代码）**：创造流程分组导航是实验壳，其中「顶层任务执行 ‖ 资产空间」**产品表述作废**；后续须先 UI 设计再改界面，禁止在错误模型上继续编码。

辅助：记忆模态、协商模态；语言切换（中/英，不混排）。

## 8. 设计原则（合并）

- 意图可见优先；提议与确认分离。  
- 归因到判断；Credit 表达有成本。  
- 可见的共生（AI 身份、立场、记忆、责任标记）。  
- 人类主权：部署、冻结、否决、阶段跃迁关键点需确认。  
- 可追溯：裁决与调度写入责任链。  
- 场景可切换、底座不分裂。  
- 垂直优先：首垂小批量结构件；产品场景先验证可组合模块数据。  
- 界面语言本地化：不中英混排（专有名词除外）。
